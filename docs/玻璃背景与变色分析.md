# 侧边栏「变色」问题与「模糊 + 实时背景」实现分析

> 记录 SideDrawer 液态玻璃背景反复变色、以及实时模糊方案为什么做不成的完整分析。
> 涉及文件：`src/Program.cs`（`FixedBackdrop()`、`RefreshGlass()`、`VeilAlpha()`、`ApplyGlassStrength()`）

---

## 一、现象

侧边栏面板的颜色会「变」：

| 场景 | 表现 |
|---|---|
| 背后是白色窗口（浏览器 / 记事本） | 面板发白，胶囊上的文字对比度明显下降 |
| 背后是深色壁纸 / 游戏 | 面板变暗，文字反而清楚 |
| 开着 Wallpaper Engine（动态壁纸） | 面板亮度持续轻微起伏，像在「呼吸」 |
| 切窗口 / 打开新程序 | 面板颜色瞬间变一次 |
| 用截图工具截屏时 | **面板看起来完全不同**（胶囊变得很实、很白） |

最后一条最关键：**截图和肉眼看到的画面不一样**，这说明问题不在「颜色值算错」，而在「合成路径」。

---

## 二、根本原因

### 1. 面板背景 = 实时截屏

原始实现的玻璃是这样做的：

```csharp
ImageSource shot = CaptureForGlass();      // CopyFromScreen：把背后屏幕拍一张
ImageBrush bb = new ImageBrush(shot);      // 当作面板背景
_glass.Background = bb;
```

也就是说，面板的「底色」不是颜色，而是**背后屏幕的一张照片**。

- 背后是白窗口 → 照片是白的 → 面板白 → 白字的对比度被吃掉
- 背后是深色 → 照片是暗的 → 面板暗 → 白字清楚

**只要背景还是截屏，面板颜色就必然跟着背后内容变**，这一点无法通过调透明度、调遮罩彻底解决，只能减轻。

### 2. 为什么截图和肉眼不一样

WPF 的 `AllowsTransparency="True"` 窗口是**分层窗口（WS_EX_LAYERED，逐像素 alpha）**。

- **正常使用时**：DWM 逐帧把窗口像素和下面的桌面**实时混合**。半透明的部分会透出「此刻」的壁纸，壁纸在动，混合结果就在变。
- **截图工具截屏时**：DWM 往往走「静态合成」路径（为了抓取完整帧），此时半透明窗口被按接近不透明的方式合成，于是面板看起来更实、更白。

所以同一份像素，在两条合成路径下观感不同。这也解释了为什么用 `CopyFromScreen` 做像素比对时经常得到「差 = 0」，但肉眼仍觉得在变。

### 3. 叠加层放大了这个问题

面板上还有多层半透明覆盖：

| 图层 | 作用 | 原始 alpha |
|---|---|---|
| `_glass.Background` | 截屏玻璃 | 18（约 93% 透明） |
| `tint`（白色渐变） | 高光/镀膜 | 52 / 18 / 34 |
| `_veil`（深色遮罩） | 压暗、提升文字对比 | `14 + 档位×6` |
| `glow`（径向高光） | 左上角光斑 | 低 alpha |
| 噪声层 | 颗粒感 | 0.6%~1.2% |

当底层是 93% 透明的截屏时，上面几层的效果**全部建立在「会变化的底」之上**，所以遮罩怎么调都只是比例上的缓解。

## 三、尝试过的方案与结果

| # | 方案 | 结果 |
|---|---|---|
| 1 | 提高胶囊不透明度（白 25% → 85%） | 减轻，但仍有变化 |
| 2 | 遮罩从 14 提到 158（固定深色） | 面板稳定了，但**音乐面板跟着变黑**（两者共用 `VeilAlpha()`） |
| 3 | 遮罩改成「上下暗、中间亮」的渐变 | 有设计感，但中间仍透壁纸，胶囊依旧会变 |
| 4 | 只改 `OpenCore()` 的背景为固定色 | **无效**——`RefreshGlass()` 每次打开都会重新截屏并覆盖 |
| 5 | 把 `RefreshGlass()` 也改成固定底色 | **有效**：面板彻底不透明、颜色恒定 |
| 6 | 在 5 的基础上把固定底色 alpha 降到 210~222（约 13% 透） | 兼顾「有点玻璃感」和「变化极小」，推荐折中 |
| 7 | 恢复原始参数（alpha 18 + 遮罩 14） | 回到「极透」观感，颜色重新随壁纸变化——**这是透明的必然代价** |

### 方案 4 是最容易踩的坑

代码里其实有**两条**设置背景的路径：

```csharp
private void OpenCore()      { ... _glass.Background = FixedBackdrop(); }   // 打开时
private void RefreshGlass()  { ... _glass.Background = bb; }                // 每次刷新
```

只改前者的效果是：**打开瞬间是固定色，随即被 `RefreshGlass()` 覆盖回截屏**，表现为「改了也没用」。
最终修复是把 `RefreshGlass()` 整个简化：

```csharp
private void RefreshGlass()
{
    ApplyGlassStrength();
    _glass.Background = FixedBackdrop();   // 永不截屏、永不透明到失控
}
```

## 四、当前实现

### 固定背景

```csharp
private static Brush FixedBackdrop()
{
    LinearGradientBrush b = new LinearGradientBrush();
    b.StartPoint = new Point(0, 0);
    b.EndPoint   = new Point(0.35, 1);
    b.GradientStops.Add(new GradientStop(Color.FromArgb(18, 18, 18, 26), 0));     // 可调
    b.GradientStops.Add(new GradientStop(Color.FromArgb(22, 24, 24, 34), 0.5));   // 可调
    b.GradientStops.Add(new GradientStop(Color.FromArgb(16, 16, 16, 24), 1));     // 可调
    b.Freeze();
    return b;
}
```

> 当前包内取的是**原始极透值（18/22/16）**。想要稳定就把三个 alpha 提到 210~250。

### 遮罩

```csharp
private int VeilAlpha()
{
    int i = 钳制(_cfg.BlurLevel, 0, 4);
    return 14 + i * 6;     // 0 档最透，4 档最实
}
```

### 音乐面板独立

音乐面板**曾经**复用同一个遮罩值（`VeilAlpha() + 10`）。侧边栏遮罩提到 158 后，音乐面板跟着变黑——因为两者共用一份数值。保留独立入口即可解耦：

```csharp
_music.SetVeil(52 + _cfg.BlurLevel * 8);   // 独立数值，不跟侧边栏联动
```

## 五、调参速查

| 想要的效果 | 改哪里 | 怎么改 |
|---|---|---|
| 完全不变色 | `FixedBackdrop()` | 三个 alpha 全设 255 |
| 轻微玻璃感、几乎不变色 | `FixedBackdrop()` | alpha 设 210~222 |
| 极透（会随壁纸变） | `FixedBackdrop()` + `VeilAlpha()` | alpha 18~22，遮罩 `14 + i*6` |
| 整体更暗 | `VeilAlpha()` | 基数从 14 提到 60~96 |
| 时钟文字更稳 | `BuildHeader()` 里的 `clockPlate` | 给它固定深色底（已实现过，可恢复） |
| 音乐面板别跟侧边栏一起变黑 | `_music.SetVeil(...)` | 传独立数值 |

## 六、想要「真·实时毛玻璃」的正确做法

截屏 + CPU 高斯模糊这条路本身就走不通（重绘成本高、颜色随内容变）。Windows 原生提供了三种正确做法：

| 方案 | API | 适用 |
|---|---|---|
| **A. Acrylic / Blur behind** | `SetWindowCompositionAttribute` + `AccentPolicy(ACCENT_ENABLE_ACRYLICBLURBEHIND)` | Win10 1803+，最接近「毛玻璃」，由 DWM 在 GPU 上完成 |
| **B. Mica / Acrylic (Win11)** | `DwmSetWindowAttribute(DWMWA_SYSTEMBACKDROP_TYPE)` | Win11 22H2+，系统级材质，最省资源 |
| **C. DWM 缩略图** | `DwmRegisterThumbnail` | 想让窗口「映出」特定窗口内容而非桌面 |

**代价**：三者都要求窗口**不是逐像素透明**（`AllowsTransparency` 必须为 `false`，改用 `WindowChrome` 做圆角/透明外框），这会影响当前的「任意形状 + 逐像素透明」画法。等于要重构窗口层。

若只是想「玻璃感 + 稳定」，本包的固定底色方案足够；若要真模糊，建议直接上 A，并把圆角改成窗口 Chrome 的圆角。

---

## 七、结论

1. **变色不是 bug，是「透明」的物理结果**：面板透出的是实时桌面，桌面变它就变。
2. **截图看不出变化也正常**：DWM 在截屏时走静态合成路径，与实时合成不同。
3. **要稳定就必须放弃实时采样**：`FixedBackdrop()` + 简化的 `RefreshGlass()` 是当前方案。
4. **要真毛玻璃就用系统合成**（A/B），不要自己截屏算模糊。
